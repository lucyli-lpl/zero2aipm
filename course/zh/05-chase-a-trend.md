# 模块 5 · 追热点不被淹没

## 为什么学这个

AI 领域几乎每个月都有新东西刷屏。全都追，就是什么都懂一点、什么都没做完；全都不理，面试时又显得落伍，因为面试官特别爱问"你玩过 X 吗？"

要练的不是跟上所有东西，而是快速判断什么值得花时间，把那少数几个快速学会，再把每一个都变成能拿出来的东西。

## 方法

### 第一步：十分钟判断

问四个问题：

1. **它解决了什么以前没解决的问题？** 找不到的话，多半只是换了包装。
2. **它会改变产品决策吗？** 产品经理会不会因为它的存在而换一种设计？（新的交互方式、新的分发渠道、新的成本结构、新的能力。）
3. **谁在背后做，还在动吗？** 看最近的发布记录或代码提交。两个月没更新的热点，通常已经过了巅峰。
4. **两小时内能上手试吗？** 光安装就要一天的话，就去读一篇好的解读，别装了。

把答案写进 `my-journey/trends.md`，带上今天的日期。大部分热点到这里就结束了，这没关系：你已经知道得足够在面试里聊了。

### 第二步：两小时动手

通过判断的，给自己设两小时上限。装上它或者用上它，用它做一件真实的事。记下哪里让你意外、哪里出了问题。两小时一到就停，哪怕正顺手。

### 第三步：写一份拆解

用五个问题把它当产品来分析：

1. **它解决了什么问题？** 以前人们怎么做这件事，AI 替代或增强了哪个环节？
2. **人机关系是怎样的？** AI 是在做决策还是给建议？用户的控制权在哪里，什么时候交给人？
3. **它怎么建立信任？** 靠透明（展示推理过程）、靠准确率的积累，还是靠错了也没大事？
4. **冷启动和数据飞轮。** 第一天没有数据怎么办，用的人越多它怎么变得越好？
5. **商业模式。** 这个能力怎么变成价值：降成本、提转化，还是创造一个新的付费点？

一页纸就够。拆解把"我试过"变成"我是这么看的"，这才是面试和同事真正想听的。

### 第四步：标上保质期

每份笔记的最后写一句："预计过时时间：___。"它让你分清自己学到的（推理，会留下来）和只是看到的（工具，会变）。

## 信息源要少

你不需要五十个订阅号。一小组稳定的信息源，胜过一个刷不完的信息流：

- 一两个 AI 实验室的一手来源（工程博客和发布说明）。
- 一位认真写实践经验的从业者。
- 一个通勤听的播客。
- 一个覆盖本地市场的信息源。
- 每月扫一次热门开源项目。
- 每天学一个新词、复习一个旧词的习惯。可以交给定时任务来做。

## 练习

1. 问 Claude 现在 AI 产品领域有什么热点。Claude 会去搜索，因为这种问题变化太快，不能凭记忆回答。
2. 用四个问题判断其中三个，存进 `my-journey/trends.md`。
3. 挑最通过判断的那个，花两小时动手，在日志里记下过程。
4. 用 `templates/teardown.md` 和五个问题写一份拆解，加上保质期那一行。
5. 让 Claude 挑战你的拆解：持反对意见的人会怎么说？

## 自测

- 三个热点里，你决定不追哪个？为什么？
- 你的拆解里，哪些内容一年后依然成立，哪怕这个产品已经没了？
- 你在两小时时停下了吗？

## 我的经历（带日期的例子）

**2026 年 3 到 4 月：OpenClaw。** 那年春天，一个能把 Agent 接进聊天软件的开源个人 AI 助手框架到处都在讨论。我装了它，接上 DeepSeek 模型，为了一场面试研究了它的产品设计。我还装了另一个 Agent 框架，它在 Windows 上跑不起来，我专门开了虚拟机，结果发现没法远程召唤它。最后，Claude Code 就覆盖了我需要的。我留下的心得是：两小时上限是有道理的，那份拆解比安装本身值钱得多。

到了秋天，OpenClaw 还在持续发版，但已经不再是焦点。

**2026 年 9 到 11 月：个人 Agent 和 bot。** 几周之内，各大公司接连发布个人助理和 bot，包括 Meta 的 Muse、OpenAI 的 Dots、阿里千问转向个人 Agent，以及 xAI 的 Grok Bot。产品问题从"Agent 能不能办事"变成了"谁拥有那个常驻在用户身边的助手"。如果你读到这里时已经更晚了，大概率又有了新的一波。用同样的四个问题去判断它。
