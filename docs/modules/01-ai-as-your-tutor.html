Why this module

The hardest part of starting from zero is not that any one idea is difficult. It is not knowing which ideas exist, which to learn first, and how they relate. This module gives you two things directly: the videos I recommend most from my own learning, and a route that strings the core terms of AI applications together in the order they appeared. You do not need to come up with the terms yourself. Just follow along.

1

The model itself

2017 — 2022 · What a large model is, and how to talk to it

2017Large language models (LLMs) and the TransformerA model that has read huge amounts of text and generates content by predicting the next word. The Transformer is the architecture underneath.

Why it appeared

Earlier language models processed words one at a time, forgot the start of long texts, and could not be trained in parallel. The 2017 paper "Attention Is All You Need" let every word look at every other word directly through attention. Models could remember long text and train in parallel, so they could grow much larger. The large-model era starts here.

Branches

  • Pre-trainingTraining on huge amounts of web text so the model has knowledge. Like going from birth to a university degree: well read, but not yet good at following instructions.
  • Post-training (SFT, RLHF, DPO)All training after pre-training. SFT teaches it to follow instructions; RLHF and DPO make it safer and more useful. Like on-the-job training.
  • Tokens and the context windowModels read, write and bill in tokens. The context window is how much they can see at once.
  • Scaling lawsMore compute, parameters and data in training make a stronger model. Since 2024, giving the model more time to think at answer time also helps.
  • Reasoning modelsModels that think internally before answering, trading time for better answers.
  • HallucinationThe model confidently makes things up. Many later techniques exist to reduce it.

Recommended

  • VideoBilibili @唐吉坷德拉曼查的英豪: explainer on "Attention Is All You Need" (highly recommended; all his videos are worth watching; Chinese)
  • VideoMu Li: close reading of the Transformer paper (for going deeper; Chinese)
  • PaperPaper: Attention Is All You Need
2020 — 2022Prompt engineeringDesigning the instructions you give the model so it produces what you want more accurately and predictably. It does not change the model, so it is the cheapest lever.

Why it appeared

As models grew, people found that the same model gave very different answers depending on how you asked. Retraining was expensive, so the first effort went into how to ask: give it a role, give examples, ask it to think step by step.

Branches

  • System and user promptsThe system prompt sets rules and persona; the user prompt is each specific request.
  • Few-shot examplesPut a few examples in the prompt so the model copies the format and style.
  • Chain of thought (CoT)Ask the model to write out its reasoning before the answer. Accuracy on hard problems improves noticeably.

Recommended

  • DocsClaude prompting best practices (official docs)
  • ArticlePrompt engineering study notes (long article, Chinese)

Teaching the model your data

2020 — 2023 · A general model knows nothing about your company. How to fill that gap

2021Fine-tuningTraining an existing model again on specific data so it suits a task better. It changes the model's parameters.

Why it appeared

Prompts can only do so much: some formats, styles and professional tones stay unreliable however you ask. Training from scratch is far too expensive, so you give an existing model extra training. LoRA trains only a small set of parameters, which brings the cost within reach of individuals and small teams.

Branches

  • SFT and LoRASFT trains on instruction-and-answer pairs. LoRA trains only a few low-rank parameters; most domain projects use it today.
  • Fine-tuning vs continued pre-trainingFine-tuning teaches the model how to answer; continued pre-training teaches it new knowledge. For format and tone, fine-tune. For a new domain, use continued pre-training or RAG.
  • Quantization, distillation, pruningWays to make models smaller and faster. Companies most often use quantization (an instant cost cut) and distillation (a small dedicated model).

Recommended

  • VideoBilibili: SFT fine-tuning with LoRA (Chinese)
  • PaperPaper: LoRA
2020 — 2023Retrieval-augmented generation (RAG)First find the relevant content in an external knowledge base, then have the model answer based on it.

Why it appeared

A model only knows what it saw in training, has a cutoff date, and has never seen your company's documents. Retraining is slow and expensive, and putting every document in the prompt is far too long. So you retrieve only the few passages relevant to the question and put those in the prompt. That is RAG, and it is the most common shape of enterprise AI apps.

Branches

  • Embeddings and vector databasesTurn text into lists of numbers where similar meanings get similar numbers, so you can search by meaning.
  • Chunking, hybrid search, rerankingAll answers to the same problem: the retrieval step found the wrong content.
  • RAG plus knowledge graphsStore key facts as entity-relation-entity triples for more accurate fact lookup, for cases where mistakes are not acceptable.

Recommended

  • PaperPaper: Retrieval-Augmented Generation

Letting the model act

2022 — 2025 · From only talking to using tools and finishing tasks on its own

2023Function callingThe model outputs, in an agreed format, which tool to call and with what arguments, and an outside system actually runs it.

Why it appeared

A model only outputs text: it cannot check today's weather or place an order. If it states in a fixed format "call get_weather, city is Shanghai", a program can run that and hand back the result. The model goes from only talking to using tools.

Branches

  • ToolsThe individual capabilities a developer gives the model, each with a name, description and parameters.

Recommended

  • DocsOpenAI function calling docs
2024MCP (Model Context Protocol)A standard interface that lets AI apps connect to tools, data and services in one consistent way.

Why it appeared

With function calling, every AI app had to build its own connection to every tool, so the same tool was rewritten many times. MCP defines one way to connect, like a USB port for AI: write a tool once and every MCP-compatible app can use it.

Branches

  • MCP vs tools vs skillsThink of cooking tomato and egg stir-fry. MCP is the kitchen door, tools are the pans and stove inside, and a skill is the recipe that takes you from the door to the finished dish.

Recommended

  • VideoBilibili: AI terms in plain words (MCP, tools, skills and more; Chinese)
  • DocsMCP official introduction
2022 — 2025AgentsA system that works toward a goal by repeating think, act, observe, and calls tools on its own to finish complex tasks.

Why it appeared

Function calling does one step at a time, so a person has to direct every step of a complex task. If the model decides the next step itself, checks the result and decides again, it can finish a whole job on its own. Prompt plus model plus tools is the simplest agent.

Branches

  • The agent loop (ReAct)Think, act, observe, and repeat until the task is done.
  • Workflow vs agentUse a fixed workflow when the steps are known: more stable and cheaper. Let an agent decide only when the steps are uncertain.
  • Agent design patternsCommon building blocks such as routing, parallel work, planning and reflection, which can be combined.

Recommended

  • ArticleHow agents work (tw93, long article, Chinese)
  • PaperPaper: ReAct
2025Multi-agent systemsSeveral specialised agents work together on a task, each with its own clean context.

Why it appeared

The more one agent does, the messier its context gets and the worse it performs. Splitting the task across specialised agents fixes that, but coordination has its own cost. So it is worth it only in a few cases: polluted context, work that can run in parallel, or a real need for specialisation.

Branches

  • When not to use itMost of the time a single agent with good tools is enough. Multi-agent setups cost far more tokens and complexity.

Recommended

  • ArticleAnthropic: when to use multi-agent systems
4

Making agents reliable

2025 — 2026 · Agents can act. How to keep them steady over long, real work

2025Context engineeringDeciding what the model sees at each step: history, knowledge and tool results, and how to filter, compress and arrange them.

Why it appeared

The longer an agent runs, the longer its context gets. History, retrieved text and tool output pile up and the model loses track of what matters. Prompt engineering is about how to phrase one request; context engineering is about which information to show at every step.

Branches

  • Compression and memorySummarise long history into key points, or store it outside and fetch it when needed.
  • Loading on demandDo not fill the context up front; add each piece when it is needed.

Recommended

  • ArticleAnthropic: Effective context engineering for AI agents
  • ArticleLangChain: Context engineering
2025Agent skillsA way of doing a job (prompts, scripts, reference files) packaged as a reusable module the agent loads when needed.

Why it appeared

Explaining the same procedure in the prompt every time is long and hard to reuse. Write it as a skill instead, and the agent reads the details only when it uses it (progressive disclosure). That saves context and makes the method shareable. It is especially good for capturing standard procedures.

Branches

  • Progressive disclosureThe agent first sees only the skill's short description and reads the full contents only when it uses it.
  • Skill vs sub-agentA skill is roughly a sub-agent that switches on when needed.

Recommended

  • ArticleAnthropic: introducing agent skills
  • DocsAgent Skills open standard
2026Personal agents and botsA private AI assistant that lives in your chat app, phone or computer and handles things for you over time.

Why it appeared

Once agents became capable, the next step was bringing them closer to people: no special website, just your chat app or phone. March to April 2026 was the peak of the open-source framework OpenClaw; the second half of the year brought a wave of personal bot launches from large companies. This node changes fast, so check what is current when you get here.

Branches

  • OpenClawThe most popular open-source personal agent framework of early 2026. One key idea was putting the agent inside chat apps.

Recommended

  • Codenanobot: a compact re-implementation of OpenClaw (good for reading the code)
2026Harness engineeringBuilding constraints, feedback and reliable context around an agent so it finishes long tasks dependably in a controlled environment.

Why it appeared

An agent that does well once may not hold up over hours or days: it forgets, drifts and grades itself too kindly. A harness is the gear for steering it: instruction management, orchestration, guardrails, evaluation and integration. However strong models get, this layer is still worth building.

Branches

  • EvalsA fixed set of test cases that measures how well the AI does. It is where all improvement starts (you build one in Module 4).
  • Guardrails and human in the loopLimit what the agent can do and put people at the decisions that matter most.

Recommended

  • ArticleAnthropic: harness design for long-running apps
  • ArticleAnthropic: effective harnesses for long-running agents
  • ArticleOpenAI: Harness engineering

Good to know

Research-heavy or domain-specific topics, optional for most AI product roles. Recognising the names and roughly what they do is enough.

  • Multimodal modelsModels that understand and generate text, images, audio and video together.
  • Diffusion models (DiT)Generate an image by wiping away noise step by step. The main method for image and video generation today.
  • GANsOne network forges, another detects, and both improve. Fast but unstable; largely replaced by diffusion.
  • Liquid neural networks (LNN)An architecture different from the Transformer, suited to continuously changing signals; seen in robotics and self-driving.
  • BenchmarksStandard exams for comparing models. Useful when choosing a model, but no substitute for evaluating your own use case.

Step 3: When you get stuck, ask from the problem

The "why it appeared" part of each node uses this course's core learning method: do not memorise the definition. Go back to the world before the idea existed, see what problem people had and why the obvious fixes failed, then derive the idea.

When a node or branch does not make sense, tell your tutor:

Teach me [term] by reconstructing it. Start from the world before it existed: what problem did people have, what did they try first, and why did that fail? Then derive [term]. Use one concrete example, under 300 words.

Tutors in this course explain this way by default. When you meet a new term that is not on the map, ask the same way, then hang it on the right stage.

Quick quiz

1A company wants an AI assistant that answers staff questions about the expense policy. The policy changes every month. What is the best approach?

Knowledge that changes often and must be quoted accurately is exactly what RAG is for. Fine-tuning teaches how to answer, not frequently updated facts, and a giant prompt is too long and too expensive.

2What problem does MCP mainly solve?

With function calling, every app had to build its own connection to every tool. MCP is like a USB port for AI: one standard way to connect.

3An agent drifts after running for several hours and forgets rules set at the start. Which area deals most directly with this?

The longer an agent runs, the messier its context. Context engineering decides what it sees at each step; harness engineering adds constraints, feedback and evaluation to keep it steady.

4You want the model to always write support replies in your company's tone and format. No new knowledge is involved. What do you try first?

Tone and format are about how to answer. Start with the cheapest lever, the prompt, and fine-tune if it is not stable. Continued pre-training is for new knowledge.

From my journey

At first I learned terms by watching plain-language explainer videos and copying definitions into a document. That helped me read industry reports, but I forgot most of it within weeks. What stayed were the ideas I actually used in a project, or rebuilt from the problem they solve. This map is what came out of later reorganising my scattered notes around one question: what problem was each technique solving?
